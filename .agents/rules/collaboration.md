# Parallel agent work

Independent subtasks may be delegated without another permission request. Use parallelism when it reduces time or gives a useful independent review; do not split trivial edits just to run more agents. Follow client/system restrictions on delegation and messaging.

- **Keep the primary checkout clean.** The repository's primary checkout stays on the default branch with no uncommitted work; it is the sync point after merges and must be switchable at any time. Every agent edits in its own task worktree, even when working alone.
- **One writer per checkout.** Each implementation agent owns a separate branch and worktree. Read-only reviewers may inspect the shared checkout; they must not run generators, formatters or commands that modify it.
- **Inspect before allocating.** Check existing worktrees and active owners; reuse a suitable idle checkout. Create new ones with `harness.py worktree new <branch>` (from the remote default branch, with an offline dependency install when the stack has one) or the client's managed worktree tool. A new worktree does not copy uncommitted work; explicitly choose a dependency commit/base before delegating.
- **Split plans with independent steps.** When a plan has two or more steps in disjoint packages, the coordinator (the session that owns the plan) may give each step to an [implementer](../roles/implementer.md) in its own worktree. It keeps the riskiest or contract-owning step itself, and has the [reviewer](../roles/reviewer.md) review each result before its PR. Parallel agents share the user's usage limits, so run two or three at a time, not more.
- **Write a small assignment.** In the active task plan record owner, branch, absolute worktree path, base/dependency, editable scope, expected output and verification. Each child creates its own scoped plan when implementing. Do not have parallel agents edit one shared tracking file.
- **Keep execution local to that worktree.** Use its absolute working directory for every command, including its own `scripts/harness.py`. Do not assume the tool's initial checkout changes when a worktree is created. Parallel servers need distinct ports. Do not share mutable dependency folders, build outputs or test-results directories.
- **Resolve dependency ownership first.** Assign shared contracts/migrations to one owner. Dependents start from the agreed committed contract or wait for it; avoid simultaneous incompatible edits. Read-only review can proceed while implementation is underway.
- **Integrate serially.** Children hand off using the [handoff template](../templates/handoff.md): commit IDs, changed files, checks and limitations. One coordinator merges/cherry-picks into the task's integration branch, resolves conflicts with the owners and runs checks for the combined behavior. The coordinator then publishes the integration branch as one PR, or one PR per step when the plan says so, under the [Git completion rules](git-workflow.md). It preserves checkout ownership and reports any integration blocker.
- **Finish recoverably.** Record which branches/worktrees remain active. Release only idle owned worktrees after integration or a recoverable snapshot/commit; use managed archive when available. Preserve untracked/ignored work that an archive would omit. Never delete or reset another agent's checkout.

Subagents can share a filesystem even when their conversations are separate. Branches alone do not isolate simultaneous edits in the same directory; separate worktrees do.
