# Java and Rust projects

- Date: 2026-09-30
- Status: In Progress (2026-10-01): steps 1 to 4 done (#50, #51, and step 3 built, awaiting review). The pilot (step 5, paid) is wave 4, after a Python or TypeScript smoke test.
- Scope: on 2026-09-30 the user asked whether Agentium works for Java and Rust, not only Go. Only Go repositories have been run for real, and several parts are Go-specific.

## Why
Findings from reading the code on 2026-09-30. None of this has been tried on a Java or Rust repository.
- **Sandbox writes and network.** The agent's sandbox has no network and can write only to its workspace and its own build cache (`internal/claude/invoke.go`). Go works because:
  - its module cache is only read;
  - `GOCACHE` points into the run's cache;
  - `-buildvcs=false` stops a stat-cache write.

  Maven (`~/.m2`), Gradle (`~/.gradle`) and Cargo (`~/.cargo`) write to their home folders and fetch missing dependencies from the network, so agents' builds would likely fail with denials.
- **Hidden-test leaks through caches.** `BuildEnv` (`internal/run/run.go`) moves Go's, Jest's and XDG caches of Agentium's own commands into the data folder. Its comment says Gradle's build cache, sccache and Bazel stay where their tools keep them, so compiled hidden tests may land where agents can read them.
- **Test-command discovery** (`internal/project`) knows go, npm/pnpm/yarn, pytest and make, not mvn, gradle or cargo.
- **Hidden-test split** (`task.IsTestFile`). Folders named `test` or `tests` work, which covers `src/test/java` and Rust's `tests/`. Two cases land in the reference instead:
  - Rust's inline `#[cfg(test)]` modules;
  - Java test classes outside a test folder.
- **Fairness check.** Identifier checks are Go-only, and `.java`, `.kt` and `.rs` are not scanned for string literals. (Literals done in step 4; identifiers added 2026-10-02, below.)
- **Grading.** The check-file map knows `Cargo.toml` but not `pom.xml` or `build.gradle`. The test-runner pattern misses `mvnw`, `mvn verify` and `cargo nextest`.

## Outcome
A Maven, Gradle (Java or Kotlin) or Cargo repository works like a Go one:
- `init` proposes its test command;
- tasks split their hidden tests correctly, or are refused with a reason;
- agents build and test offline in the sandbox without denials;
- agents cannot read compiled hidden tests;
- the fairness check scans its string literals.

Go's behavior does not change.

## Design
- **Build-tool profiles.** One table of profiles (Go, Maven, Gradle, Cargo), each listing:
  - the files that detect it and its default test command;
  - the test-runner configuration files;
  - the environment variables to allowlist;
  - the caches to redirect for Agentium's own commands, and the user's caches to deny to agents;
  - how the agent gets dependencies offline.

  Go's special cases move into its profile unchanged. A new package, if needed, is added to the architecture's code map.
- **Dependencies offline.** Setup and grading have network; they warm dependencies, and agents read them without writing. Step 1 verifies these candidates before any code is written:
  - Maven: a read-only tail repository (`maven.repo.local.tail`) with `-o`;
  - Gradle: a read-only dependency cache (`GRADLE_RO_DEP_CACHE`) with `--offline`;
  - Cargo: `cargo fetch` in setup, then `--offline`, with a per-run `CARGO_HOME` if the lock files need writing.

## Acceptance
1. **Recipes.** For each of Maven, Gradle and Cargo, a short real Claude Code session in a run's sandbox builds and tests a small project offline with no sandbox denials. *Evidence:* the recipe and a summary of each session in this plan.
2. **Discovery and grading.**
   - `init` proposes `mvn -q test` or `./mvnw -q test`, `./gradlew test` or `gradle test`, and `cargo test`.
   - Grading knows each tool's configuration files.
   - The test-runner pattern covers `mvnw`, `mvn verify` and `cargo nextest`.

   *Evidence:* unit tests with fixture repositories.
3. **Hidden tests.**
   - Java and Kotlin classes named `*Test`, `*Tests` or `*IT` count as tests anywhere except under `src/main/`, when a lowercase letter or digit comes before the suffix.
     - *Changed on 2026-10-01 after review; the user accepted it by merging #48:* the first wording made production classes such as `RetryingTest.java` under `src/main/java` (likely in junit-pioneer), `GIT.java` or `AUDIT.kt` hidden tests. That would hand the reference's version of a production file to every agent.
   - A Rust solution that changes `#[cfg(test)]` or `#[test]` code inside a non-test file is refused at `task import`, `task add` and `task validate`, with the reason, instead of leaking tests into the reference.

   *Evidence:* hermetic tests.
4. **No leaks.** For each profile:
   - Agentium's own commands keep their build caches in the data folder, or disable them (for example, clearing `RUSTC_WRAPPER` for sccache);
   - the agent is denied the user's caches that may hold compiled tests.

   *Evidence:* tests of the environment and denied paths, and in step 5 a search of agent-readable caches for hidden test names after validation and grading.
5. **Fairness.** String literals in `.java`, `.kt` and `.rs` test files are scanned. Java text blocks and Rust raw strings are either handled or listed as limitations. *Evidence:* fixtures with one unstated literal each.
6. **Go unchanged.** Existing tests pass unmodified, and a Go project's agent environment and denied paths are identical to today's. *Evidence:* a golden test written before the refactor.
7. **Pilot.** On the three repositories under Decisions:
   - `init`, then import 2–3 tasks each and validate them;
   - then one real run per task in the base context.

   Every run ends `ok` or with a genuine test failure, with no build-tool denials, and is graded. *Evidence:* the runs' outcomes and denial counts in this plan.
8. **Docs:** the architecture's code map, and the README's requirements and supported languages.

## Decisions (the user, 2026-09-30)
- **Tools come from wrappers.**
  - Maven and Gradle come from each repository's `mvnw` or `gradlew`; discovery prefers a wrapper when present.

## Pilot finding: identifiers in Java, Kotlin and Rust (2026-10-02)
- **Gap:** junit-pioneer `add-reproducible-disableduntil-dates-92af6e0` is graded by a hidden test that statically imports `DisabledUntilExtension.EXECUTION_DATE_CONFIGURATION_PARAMETER`, which neither the instruction nor the base states. The fairness check scanned only literals for these languages.
- **Fix** (`internal/task/fairness_names.go`): a hidden `.java`, `.kt` or `.rs` file's newly used names (imports, static imports, qualified references, `Type::item`) are flagged as identifier gaps when the reference declares them (found by pattern), the test does not declare them itself, the instruction does not mention them and no base file of the language family (Java and Kotlin together; Rust alone) has the word. JDK, standard-library and dependency names are never declared by the reference, so they are never flagged.
- **Real check (free, pilot data folder):** the task now lists `EXECUTION_DATE_CONFIGURATION_PARAMETER`; the Rust bytes tasks list nothing; jackson-core lists `resetWithASCII` and `resetWithUTF8` for one task; junit-pioneer's jitter task lists `jitterSeed` (an annotation element) and `maxJitterMs`.
- **Review follow-up:** test-side locals and parameters hide a name (a collision with a reference's private field is no gap); annotation elements and modifier-less interface methods count as declarations; overrides and Rust trait-impl methods do not; a switch `default:` is no declaration.
- **Limits:** names under 4 characters are skipped; a new name equal to any base word is missed; enum constants are not seen as declarations; Kotlin generic functions with nested `>`, Kotlin constructor parameters without `val` or `var`, and Rust `pub use` re-exports are missed; there is no scoping or type resolution.
