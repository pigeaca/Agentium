# LLM judge per run

- Date: 2026-10-01
- Status: In Progress (2026-10-01): step 1 merged (#49); step 2 in its PR (approved after two reviews). Step 3 (reports) is next. The user approved the step 4 real check with the [next chapter](2026-10-01-next-chapter.md).
- Scope: the user's [decision](../decisions/2026-10-01-llm-judge-alongside-tests.md) after the [judge pilot](../../docs/research/2026-10-01-judge-pilot-results.md). The user chose:
  - a per-run verdict;
  - shown alongside the tests, never deciding;
  - opt-in per experiment;
  - built before Java and Rust.

## Why
A test pass is the only grade today. The pilot's judge flagged 18 of 40 passing runs as not fully fixed, each with a concrete reason. Its accuracy is unmeasured, so reports show it as a second opinion that a user can check.

## Outcome
- **Turning it on:** `experiment new ... --judge` turns the judge on, with optional `--judge-model`, `--judge-effort` and `--judge-repeats`.
- **Cost before it starts:** the preview shows the judge's cost, and the budget reserves it.
- **Each graded run:** it gets a judge verdict (fixed, partly or no), the repeats' answers and a one-line reason, stored with the run.
- **Reports:** each arm shows the share of runs judged fixed (with intervals), split by test result. Passing runs the judge flags are listed with their reasons.
- **Verdicts unchanged:** pass and fail, the success and cost verdicts, and the arms' cost metrics stay exactly as today.

## Design
- **`internal/judge`** (new package):
  - It builds the prompt from the pilot's tested wording, quoted in the [protocol](../../docs/research/judge-pilot/protocol.md#judge): system prompt, single prompt and schema.
  - The reference diff is `git diff base solution` over the task's reference files, without tests (`task.IsTestFile`) or documents (`claudectx.IsDocument`).
  - The candidate is the run's `agent.diff`, filtered the same way.
  - Each diff is cut at 40,000 characters, with a note.
  - It calls Claude Code, parses and validates the answer, and takes the majority of the repeats; with no majority, the verdict is "partly", as in the pilot.
  - The contract, owned by step 1:
    ```go
    type Verdict struct { Fixed string; Answers []string; Reason string; Model, Effort string; CostUSD float64; Errors []string; Truncated bool }
    func Judge(ctx context.Context, in Input, call Caller) (Verdict, error)
    ```
- **The call** (`internal/claude`, a judge invocation):
  - `claude -p` with `--tools ""`, `--system-prompt`, `--json-schema` and `--output-format json`;
  - project settings only, no MCP servers and no session kept;
  - an empty folder in the data folder as its working folder;
  - the same environment allowlist and sign-in as runs;
  - `--max-budget-usd` caps each call.
- **Errors:** a malformed answer is asked again once. A call that gets no answer (an error result, the usage limit or a timeout) leaves that repeat out and is recorded. If no repeat answers, the run has no verdict, with a note. A judge error never fails or reruns the agent's run.
- **Where it runs:** right after grading, inside the run's slot, so concurrency stays bounded. Resuming an experiment judges graded runs that have no verdict yet.
- **Money:**
  - The run's cap reserve gains `repeats × judge call cap`, so spending never passes the budget.
  - The judge's cost is stored apart from the agent's: `Metrics.CostUSD` and the cost metric never include it.
  - The preview estimates the judge at the pilot's $0.065 per call, as a stated figure.
- **Storage:** `run.Record.Judge *judge.Verdict` sits in the record JSON, with no migration. The lock records the judge's settings.
- **Report:** a Judge section for the terminal, Markdown and JSON. Each arm shows fixed, partly and no among passing and failing runs, with Wilson intervals; flagged passing runs are listed with their reasons (scrubbed like other text); then repeat agreement and judge cost. A line states that the judge's verdicts are a second opinion that decides nothing.

## Acceptance
1. **Judge core:** unit tests with a fake Claude Code cover:
   - prompt and schema, word for word from the pilot;
   - code-only diffs and the cut;
   - majority and the no-majority rule;
   - a malformed answer asked again, an error result, a timeout, and no repeat answering.
2. **The invocation:** no tools, no MCP servers, the allowlisted environment, and a budget cap. *Evidence:* a test of its arguments and environment.
3. **Experiments:**
   - `--judge` and its options are validated and locked;
   - the preview shows the judge's estimated cost;
   - the budget reserve includes it;
   - the judge's cost stays out of `CostUSD` and the cost metric;
   - resume judges graded runs that have no verdict.

   *Evidence:* hermetic CLI tests with a fake Claude Code.
4. **Real check (paid; approval):** a small A/B with `--judge`, 2 tasks × 1 run per arm. Every graded run gets a verdict, and the report shows the Judge section. *Evidence:* the console sample and costs in this plan.
5. **Report:** the Judge section in all three formats. A report without the judge is unchanged (golden files). *Evidence:* golden tests and a real console sample.
6. **Docs:** the architecture's code map (`internal/judge`), the README, and `experiment new --help`.

- [x] **2. Experiments:** design flags, lock, preview, budget, judging after grading, and resume.
  - **How it works:**
    - `--judge` (`--judge-model`, `--judge-effort`, `--judge-repeats`) is locked.
    - Each run's reserve gains repeats × 2 × $1, and the preview shows the judge at the pilot's $0.065 a call.
    - The judge's cost lives in `Record.Judge` only: it counts toward the budget, `show` and the report's spend, never toward the cost metric, the estimates or the analysis.
    - Judging runs after grading, in the records folder. A judge error never changes the run.
    - A usage limit pauses the experiment, which is not "done" while runs need the judge.
    - A resume judges what is missing. Runs that can never be judged get a final, cost-free verdict.
    - Records are redacted before judging, each call's cost is written to the start file as it lands, and `Recover` stores the partial verdict and removes the judge folder.
    - `agent.diff` is pinned (`--no-renames`, `a/` and `b/` prefixes).
  - **Review:**
    - First pass: changes requested (redaction after a crash, a false "done").
    - Second pass: approved with notes.
  - **Limitations:**
    - `--wait` does not wait for judge pauses.
    - The usage gate's estimate leaves out the judge's subscription use.
    - A crash during a resume's judgement loses at most that judgement's spend.
    - A transient `ReferenceDiff` error is treated as final.
    - A slot can be held for up to repeats × 10 minutes.
  - **For step 3:**
    - When every slot settled and only judge verdicts are missing, the report should say the verdicts are complete and N runs lack a judge verdict.
    - A budget too small to judge should end with the budget status (exit 0) and its `--budget` hint, not as stopped.
  - From the step 1 review:
    - Grading pins `agent.diff`: `--no-renames`, and the prefixes (`--src-prefix=a/ --dst-prefix=b/`, with `diff.noprefix` and `diff.mnemonicPrefix` off).
    - The same `Settings` go to `Judge` and `ClaudeCaller`.
    - Timed-out calls do not stop a judgement, so a run's slot can be held for up to repeats × 10 minutes; the execution window must allow for it.
    - The reserve is repeats × 2 × the call cap, since a malformed reply is asked again. `--max-budget-usd` is checked after a turn, so it is an estimate, not a hard limit.
    - A `Verdict.Stopped` for a usage limit pauses the experiment, as `UsageGate` does.
    - Resume tells "not judged" (no verdict) from "judged, no answer".
    - Reports scrub reasons and errors.
    - A task whose reference has no code gets no verdict, with a note.
