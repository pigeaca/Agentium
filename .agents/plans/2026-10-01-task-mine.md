# Task mining

- Date: 2026-10-01
- Status: In Progress (2026-10-01): step 1 under way. Approved with the [next chapter](2026-10-01-next-chapter.md). It runs no agents and makes no paid calls.
- Scope: the biggest step toward time to first verdict. A verdict needs 8–20 valid tasks, and today each is imported, reviewed and validated by hand.

## Why
`task import --commit` already turns one commit into a task: its parent is the base, its test-file changes are the hidden tests, its other changes are the reference. Finding good commits, importing them, and learning which ones fail validation is the slow part. A repository's own history usually holds dozens of candidates.

## Outcome
- **`agentium task mine`** scans the repository's history (local git only), with `--since DATE`, `--limit N` (default 20), `--max-files N` and `--dry-run`.
  - It lists candidate commits with a score and the reason for it.
  - Without `--dry-run`, it imports the best ones as tasks that need review, and validates them in one batch.
  - It ends with one table: name, commit, hidden tests, files, and status with its reason.
- **What counts as a candidate:** a non-merge commit on the default branch that changes both test files and code files.
  - It is small (files and lines under limits) and not a dependency bump, generated code or a formatting sweep.
  - Its tests can be split by today's rules: no inline Rust tests, and Java or Kotlin test classes found.
- **Ranking:** a clear message (it becomes the instruction), a moderate size, both tests and code changed, and recency.
- **Repeat runs:** mining again skips commits that are already tasks.
- **`agentium task validate --all`** (or `--status unvalidated`) validates every matching task, a few at a time, and prints the same table.
- **Validation is local:** it builds and runs tests on the host, with no agent runs.

## Design
- **A new package, `internal/mine`:** scans with `gitx` (`log` with numstat), classifies files with `task.IsTestFile` and `claudectx.IsDocument`, and filters and scores candidates. The scores are explainable, never a black box.
- **Importing and validating reuse `task import` and `task validate`.** Their logic moves behind functions the CLI and the miner share, if it is not already behind them.
- **Concurrency:** batch validation runs `--jobs N` at a time (default 2). It is cancellable, and an interrupt keeps whatever finished.
- **Review stays.** Mined instructions come from commit messages, so every mined task needs review. The fairness check flags texts the hidden tests need that nothing states.

## Acceptance
1. **Scanning and scoring:** a fixture repository with good, too-large, docs-only, dependency-bump, test-only, merge and inline-Rust-test commits gives the expected candidates, order and reasons. *Evidence:* unit tests.
2. **Mining:** `task mine --dry-run` lists candidates without saving anything. `task mine` imports and validates them, and mining again skips existing tasks. *Evidence:* CLI tests.
3. **Batch validation:** `task validate --all` respects `--jobs`, can be cancelled, and gives one table of reasons. *Evidence:* CLI tests.
4. **Real check (free: no agent runs):** mining Agentium's own repository finds at least 8 valid candidates. *Evidence:* the console sample and the time it took, in this plan.
5. **Docs:** the README quick start uses `task mine`; help.
