## Why: what breaks today
Findings from reading the code on 2026-10-02. No Python or TypeScript repository has been run for real. Discovery and the hidden-test split already know both; the sandbox and the build tools do not.
- **No profile.** `internal/buildtool` has Go, Maven, Gradle and Cargo. For a Python or JS repository `Select` returns only Go's `Always` profile: no deps folder, no warm-up, no `PrepareRun`, no denied user caches, no `Languages`.
- **No dependencies offline.** The sandbox has no network and writes only the checkout and the run's build cache.
  - *Python:* `python3 -m pytest` runs against the host's interpreter. `pytest` itself and the project's dependencies exist only if the user has them globally; `pip install` fails offline, and `uv`/`poetry` write `~/.cache` and `~/.local`. A venv built by the user is not passed: `VIRTUAL_ENV` is allowlisted, but a venv under the user's home is outside the readable set unless the user's setup put it there, and it is the user's own, not one built from the task's base.
  - *TypeScript:* `node_modules/` is absent from a fresh depth-1 checkout (it is untracked). `npm test` then fails at once (`jest: not found`). `npm ci` needs network; npm and pnpm write `~/.npm`, `~/.local/share/pnpm`.
- **Hidden-test leaks.** `BuildEnv` redirects `XDG_CACHE_HOME` and `TMPDIR` for Agentium's own commands (this covers Jest's cache in TMPDIR and `~/.cache/pip`, `~/.cache/uv`). But nothing yet handles:
  - `__pycache__/*.pyc` and `.pytest_cache/` in a checkout, hypothesis's `.hypothesis/`, `.mypy_cache`, `.ruff_cache`: they land in the checkout, which is safe only while grading and validation never use a checkout an agent can read;
  - `tsbuildinfo`, `node_modules/.cache`, `node_modules/.vite`, `node_modules/.vitest`, `.jest-cache`: in-tree, same rule;
  - the user's own `~/.cache/pytest`, `~/.cache/pip`, `~/.cache/uv`, `~/.npm`, pnpm's store, `~/.cache/jest`, and `~/.cache/typescript`: where an earlier build by the user may have compiled or cached hidden tests. They are not in `UserCaches`, so agents may read them.
- **Test-file rules** (`task.IsTestFile`) already cover `test_*.py`, `*_test.py`, `tests.py`, `conftest.py`, `*.test.*`, `*.spec.*`, and folders `test`, `tests`, `spec`, `__tests__`, `__fixtures__`, `__snapshots__`, `e2e`. Gaps: a `conftest.py` is a hidden test even when it holds production fixtures that a library's own tests export; `testing.py` and `*_tests.py`-style names, a `test_utils/` helper package and `src/**/testing/` are not matched; TypeScript `*.test-d.ts` (type tests) and `*.bench.ts` are not matched; Vitest in-source tests (`if (import.meta.vitest)`) and Python doctests land in the reference (the Rust `#[cfg(test)]` problem; Rust got a refusal).
- **Fairness.** Literal scanning already covers `.py`, `.ts`, `.js`. `fairness_names.go` knows Java, Kotlin and Rust only: a hidden pytest or Jest test that imports `from pkg import new_helper` or an unstated exported name is not flagged. This is the junit-pioneer gap again.
- **Grading and discovery.** `init` proposes `npm test`, `pnpm test`, `yarn test` and `python3 -m pytest`, always the host's `python3`, never the project's venv (`uv run pytest`, `poetry run pytest`, `.venv/bin/pytest`). `checkFiles` knows `pytest.ini`, `pyproject.toml`, `tox.ini`, `jest.config.*`, `vitest.config.*`, `package.json`, but not `tsconfig.json`, `vitest.workspace.*`, `uv.lock`, `poetry.lock`, `requirements*.txt`, `package-lock.json`, `pnpm-lock.yaml`. The test-runner pattern knows `pytest`, `python -m pytest|unittest`, `npm|pnpm|yarn|bun test`, `jest`, `vitest`, but not `uv run`, `poetry run`, `tox`, `nox`, `npx`, `pnpm exec`.
- **Task mining.** No profile has `Languages`, so `task mine` cannot narrow commits to ones whose tests the project's tools run.
- **Credentials.** `.npmrc` and `.pypirc` are in the denied credential files, good. `PIP_*`, `UV_*`, `PYTHON*`, `NODE_*` and `PNPM_HOME` pass the allowlist unfiltered, so a user's `PIP_INDEX_URL` (which may embed a token; `runner.IsCredential` drops only obvious names), `UV_CACHE_DIR`, `PYTHONPATH` or `NODE_OPTIONS` can point the agent at the user's caches or at other code.

## Outcome
A pytest repository (uv, poetry or pip) and a jest or vitest repository (npm or pnpm) work like a Go one: `init` proposes the right test command; tasks split hidden tests correctly or are refused with a reason; agents run tests offline in the sandbox with no denials and cannot read compiled hidden tests; the fairness check flags unstated names. Go, Java and Rust behavior does not change.

## Decision: Python first
Both are common; the recommendation rests on difficulty offline.
- **Python first.**
  - Dependencies live outside the checkout, so Agentium's existing model applies unchanged: warm once into `<deps>`, agents read, never write.
  - Pure-unit pytest suites need no build step, so there are no `tsc` or bundler caches to chase, and runs are cheap.
  - Risks: an interpreter the venv binds to (resolve it on the host, as `JAVA_HOME`), the project's own importability (the venv holds dependencies only; the checkout goes on `sys.path`), and `.pyc`.
- **TypeScript second**, same recipe, with these differences:
  - `node_modules/` belongs inside the checkout, so setup clones the warmed tree into the run's checkout (`cp -Rc`, as Gradle's wrapper distribution), per run;
  - native addons and `postinstall` scripts run on the host at warm-up;
  - more in-tree caches (`tsbuildinfo`, `.vite`, jest `cacheDirectory`).

  It follows once the Python step proves the profile shape; its spike runs in parallel with the Python pilot, if the user approves.

## Design
- **Profiles `python` and `typescript`** (`internal/buildtool`, one file each), selected by `Detect` at the base commit's root: Python `pyproject.toml`, `setup.py`, `setup.cfg`, `requirements.txt`, `uv.lock`, `poetry.lock`; TypeScript `package.json` with `tsconfig.json` or a ts test config (a plain JS package is covered by the same profile, `Languages: javascript, typescript`). Each gives `TestCommand`, `Languages`, `Runners`, `Configs`, `TestPatterns`, `EnvNames`/`EnvPrefixes`, `UserCaches`, `Warm`, `AgentEnv`, `PrepareRun`. Package-manager choice comes from the lock file (`uv.lock`, `poetry.lock`, `pnpm-lock.yaml`, `package-lock.json`); no lock file: dependencies are resolved once at warm-up, the pinned set is kept in the deps stamp, and the run gets a warning (the user, 2026-10-02).
- **Dependencies offline** (the Java/Rust model; trusted-repository rule: install scripts and build backends run on the host at setup, as Gradle's scripts do).
  - *Warm-up* (Python: step 1's recipe below supersedes these lines where they differ) runs once per base commit and tool set, in the throwaway checkout under `<data>/cache/warm`, with network, writing `<deps>/<project>`:
    - uv: `UV_CACHE_DIR=<deps>/uv-cache uv sync --frozen --no-install-project` into a venv at `<deps>/venv`, with `UV_PROJECT_ENVIRONMENT=<deps>/venv` and a pinned interpreter (`UV_PYTHON` or `--python <host python>`);
    - poetry: `POETRY_VIRTUALENVS_PATH`/`POETRY_CACHE_DIR` into the deps folder, `poetry install --no-root`;
    - pip: `python3 -m venv <deps>/venv` then `pip install -r` the lock or requirements files;
    - npm: `npm ci --ignore-scripts=false` with `npm_config_cache=<deps>/npm-cache`, then the result tree is stored as `<deps>/node_modules/<base-hash>`; pnpm: `pnpm install --frozen-lockfile --store-dir <deps>/pnpm-store`, with `--offline` after warm.
  - *Agent environment:* Python: `VIRTUAL_ENV=<deps>/venv`, `PATH` begins with its `bin`, `PYTHONPATH` is the checkout (and `src/` when present), `PYTHONPYCACHEPREFIX=<run cache>/pycache`, `PIP_NO_INDEX=1`, `PIP_DISABLE_PIP_VERSION_CHECK=1`, `UV_OFFLINE=1`, `UV_NO_SYNC=1`, `UV_FROZEN=1`, `UV_PYTHON_DOWNLOADS=never`, `UV_PROJECT_ENVIRONMENT=<venv>`, `UV_CACHE_DIR=<run cache>/uv`, `PYTEST_ADDOPTS=-p no:cacheprovider` (so `.pytest_cache` is not written), `HYPOTHESIS_STORAGE_DIRECTORY=<run cache>/hypothesis` (not verified in step 1: neither repository uses hypothesis). The user's `PYTHONPATH`, `PIP_*`, `UV_*`, `VIRTUAL_ENV` are replaced, not passed. TypeScript: setup clones the warmed `node_modules` into the checkout (`cp -Rc`), `npm_config_offline=true`, `npm_config_cache=<run cache>/npm`, `npm_config_update_notifier=false`, pnpm's `--store-dir` read-only and `--offline`; `NODE_OPTIONS` cleared; `PATH` unchanged beyond `node_modules/.bin` (npm adds it).
  - *Read-only by construction:* `<deps>` is already read-only to agents and denied for writes. The venv is read-only; interpreter bytecode goes to the per-run `PYTHONPYCACHEPREFIX`. A venv installs the project's dependencies only, never the project itself, so no editable install can point at the throwaway warm-up checkout.
  - *Warm-up leak rule* (the finding of the Java pilot): a later base holds earlier tasks' hidden tests as ordinary tests, so the warm-up must not run tests or compile the project. It installs and imports nothing of the project: no `pytest --collect-only`, no `tsc`, no `jest`. Wheels and tarballs in the stores come from the lock files only. Search the deps folder for hidden test names in the pilot.
  - *Stamps, locks and waits* are the existing ones (`cache/warm-state`, 15 min wait). The recipe's version covers the interpreter path and package-manager version.
- **Denied caches** (`UserCaches`, global like the others): `~/.cache/pip` and, on macOS, `~/Library/Caches/pip`; `~/.cache/uv` (uv's location on macOS too); `~/.cache/pypoetry` and `~/Library/Caches/pypoetry`; `~/.cache/pytest`, `~/.cache/ruff`, `~/.cache/jest`, `~/.cache/typescript`, `~/.npm`, `~/.local/share/pnpm` and `~/Library/pnpm`, `~/.yarn`, `~/.bun`; also `UV_CACHE_DIR`, `POETRY_CACHE_DIR`, `PIP_CACHE_DIR`, `npm_config_cache`, `PNPM_HOME` and a venv pointed at by `VIRTUAL_ENV` when set in the user's environment, the deps folder's own `uv-cache` and `pip-cache` (agents need only the venv), and the Jest and Vitest `cacheDirectory` where config sets one (a text match, like Cargo's `target-dir`; fail closed; limitation noted). Never denied: `~/.local/share/uv/python`, where the uv-managed interpreter a venv links to lives. Agentium's own commands (`CommandCaches`): the same variables into `<data>/cache/<tool>`, `PYTHONDONTWRITEBYTECODE` unset but `PYTHONPYCACHEPREFIX=<data>/cache/pycache`, so grading and validation leave no `.pyc` or `.pytest_cache` for later readers. In-checkout caches are safe only because validation and grading use their own checkouts; the spike and a test must confirm it.
- **Test-file rules** (`internal/task`): add `*_tests.py`, `testing.py`, `test_utils/`, `*.test-d.ts`, `*.bench.ts` and `*.spec-d.ts`; keep `conftest.py`. Refuse at import, add and validate a solution that changes a Python doctest or a Vitest in-source test inside a non-test file (the Rust refusal's model, `rusttests.go`), with the reason. Decide the `testing.py`/`test_utils` names by the pilot's data, not guesswork.
- **Fairness:** `fairness_names.go` gains Python (`import`, `from x import y`, `def`/`class` at module and class scope, constants; `__all__`) and TypeScript (`import { x }`, `export` declarations, `type`, `interface`, `enum`, qualified references). Same rules as the JVM family: names the reference declares, the test does not declare, the instruction and base never mention. Dependencies are never declared by the reference, so never flagged. Python `.py` and TS `.ts`/`.tsx` form one family each; `.js` joins TypeScript's.
- **Grading and discovery:** add the lock and TS config files to `Configs`, and the runners above to `Runners`/`TestPatterns`. `init` proposes the venv's runner first (`uv run pytest`, `poetry run pytest`, else `python3 -m pytest`); `pnpm test` or `npm test` as today.
