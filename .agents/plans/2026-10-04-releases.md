# Releases: a versioning policy and automated release tooling

- Date: 2026-10-04
- Status: In Progress (review round 1 addressed)
- Scope/approval: the user (2026-10-04): add to the harness what a new version means (1.2, 2.0 ...) and automate the process; releases are "fully automatic" once the first exists. The first release, v0.1.0, is gated by a checklist and cut explicitly.

## Outcome and boundaries
- A short policy, [releases](../rules/releases.md): SemVer applied to Agentium's contract (commands and flags, exit codes, `--json` keys, data folder and schema, locked experiments, report formats), with the pre-1.0 rule.
- `agentium version` reports the module version a `go install ...@vX.Y.Z` records; a checkout build shows `dev+<revision>[.modified]`; a `go install @main` build shows its pseudo-version.
- Harness commands `release plan` and `release cut`, an automatic release after `pr land` merges, and a PR-time check that detected contract changes are declared. Logic in `scripts/release.py` (Python standard library, `git` and `gh` only).
- **Detection is a committed contract golden** (`internal/cli/testdata/contract.golden`), generated from the real code by `TestContractSurface`: commands, every flag's name, type and default (from the real flag sets, through a tiny `Env.flagSink` hook in `parseArgs`), exit codes, `--json` schemas (reflection over an explicit list of document types, itself checked against the source), migrations with a content hash, design and method versions. The release tool diffs it between the last tag and the commit: removed or changed lines are breaking, added lines additive; renames and moved files change nothing. `Contract: none - <reason>` in a PR body overrides a false positive.
- **Released means published on the remote.** Every cut first reconciles a half-done release (unpushed local tag deleted; pushed tag without a GitHub Release gets one from the tag message). `release cut` works on the fetched default-branch commit, never the current checkout; `--local-checks` use a temporary detached worktree at that commit.
- Side effects: `release cut` creates an annotated tag, pushes it over HTTPS and creates a GitHub Release (no binaries). No commit to main, no CHANGELOG.md. `pr land` ends with one line (`published <url>`, `nothing to release`, `NOT released: <why>`) and exits 3 when the merge succeeded but a due release failed.
- Not in scope: workflow changes, binaries, Go packages other than the version wiring and the contract test.
- Known limit: the golden sees only what it lists; a changed meaning is seen only when a PR declares it.

## Acceptance
- `release plan` with no tag proposes v0.1.0; with a tag it computes the larger of the declared and the detected bump; pre-1.0 and post-1.0 rules are tested; nothing releasable says so and exits 0.
- The golden diff is tested on a fixture repository: removed constant-named flag and removed lint JSON key are breaking, changed values breaking, additions additive, an unchanged golden detects nothing. In Go: the golden is current, every `--json` document type is listed, the schema ignores type names; mutation checks: renaming an internal JSON type leaves the golden unchanged, removing a flag or a JSON key fails it.
- `release cut` refuses (tested) on: fetch failure, red or cancelled CI, pending CI after the timeout, an existing remote tag, nothing due, the first release without `--first`. Half-done states are tested: a local tag whose push failed, a pushed tag whose release creation failed, a dry run that changes nothing. It tags the fetched commit from a dirty task branch without moving any branch; checks run in a detached worktree removed even on failure; tag messages keep `#` headings.
- `pr land` (fake `gh`): undeclared contract changes refused with the detection printed; `Contract: none - <reason>` overrides; after a merge it releases unless `--no-release`; failure prints `NOT released`, the merge stands, exit 3.
- `agentium version` cases (ldflags, tag, checkout, pseudo-versions, `+dirty`, no VCS data) tested.
- `check changed` and `GOPROXY=off go test -race -count=1 ./internal/cli ./cmd/agentium` pass; `release plan` on this repo gives a real sample.
