# LLM judge per run

- Date: 2026-10-01
- Status: Done (2026-10-01): steps 1–3 in #49, #54 and #61; step 4, the small real check, passed (recorded below; paid, approved with the [next chapter](../2026-10-01-next-chapter.md)).
- Scope: the user's [decision](../../decisions/2026-10-01-llm-judge-alongside-tests.md) after the [judge pilot](../../../docs/research/2026-10-01-judge-pilot-results.md). The user chose:
  - a per-run verdict;
  - shown alongside the tests, never deciding;
  - opt-in per experiment;
  - built before Java and Rust.

## Why
A test pass is the only grade today. The pilot's judge flagged 18 of 40 passing runs as not fully fixed, each with a concrete reason. Its accuracy is unmeasured, so reports show it as a second opinion that a user can check.

## Outcome
- **Turning it on:** `experiment new ... --judge` turns the judge on, with optional `--judge-model`, `--judge-effort` and `--judge-repeats`.
- **Cost before it starts:** the preview shows the judge's cost, and the budget reserves it.
- **Each graded run:** it gets a judge verdict (fixed, partly or no), the repeats' answers and a one-line reason, stored with the run.
- **Reports:** each arm shows the share of runs judged fixed (with intervals), split by test result. Passing runs the judge flags are listed with their reasons.
- **Verdicts unchanged:** pass and fail, the success and cost verdicts, and the arms' cost metrics stay exactly as today.

## Design
- **`internal/judge`** (new package):
  - It builds the prompt from the pilot's tested wording, quoted in the [protocol](../../../docs/research/judge-pilot/protocol.md#judge): system prompt, single prompt and schema.
  - The reference diff is `git diff base solution` over the task's reference files, without tests (`task.IsTestFile`) or documents (`claudectx.IsDocument`).
  - The candidate is the run's `agent.diff`, filtered the same way.
  - Each diff is cut at 40,000 characters, with a note.
  - It calls Claude Code, parses and validates the answer, and takes the majority of the repeats; with no majority, the verdict is "partly", as in the pilot.
  - The contract, owned by step 1:
    ```go
    type Verdict struct { Fixed string; Answers []string; Reason string; Model, Effort string; CostUSD float64; Errors []string; Truncated bool }
    func Judge(ctx context.Context, in Input, call Caller) (Verdict, error)
    ```
- **The call** (`internal/claude`, a judge invocation):
  - `claude -p` with `--tools ""`, `--system-prompt`, `--json-schema` and `--output-format json`;
  - project settings only, no MCP servers and no session kept;
  - an empty folder in the data folder as its working folder;
  - the same environment allowlist and sign-in as runs;
  - `--max-budget-usd` caps each call.
- **Errors:** a malformed answer is asked again once. A call that gets no answer (an error result, the usage limit or a timeout) leaves that repeat out and is recorded. If no repeat answers, the run has no verdict, with a note. A judge error never fails or reruns the agent's run.
- **Where it runs:** right after grading, inside the run's slot, so concurrency stays bounded. Resuming an experiment judges graded runs that have no verdict yet.
- **Money:**
  - The run's cap reserve gains `repeats × judge call cap`, so spending never passes the budget.
  - The judge's cost is stored apart from the agent's: `Metrics.CostUSD` and the cost metric never include it.
  - The preview estimates the judge at the pilot's $0.065 per call, as a stated figure.
- **Storage:** `run.Record.Judge *judge.Verdict` sits in the record JSON, with no migration. The lock records the judge's settings.
- **Report:** a Judge section for the terminal, Markdown and JSON. Each arm shows fixed, partly and no among passing and failing runs, with Wilson intervals; flagged passing runs are listed with their reasons (scrubbed like other text); then repeat agreement and judge cost. A line states that the judge's verdicts are a second opinion that decides nothing.

## Limitations
- **The judge's reserve dwarfs its cost.** A run holds repeats × 2 × $1 for its judgement: $6 at 3 repeats, against an observed $0.05–$0.14. With concurrency 2, the reserve was $27, so the plan warned that a $25 budget would stop the experiment early, although it spent $2.23. A per-call cap near $0.25 would keep the guarantee with a smaller reserve. Fixed by the judge call cap change (`claude/fix/judge-call-cap`): `judge.CallCapUSD` is now $0.50 (not the $0.25 the limitation suggested, because the dearest observed call, a cold one that wrote the prompt cache, cost $0.33), the one constant behind every reserve, budget check and preview ($3 at 3 repeats; $6 a run with a $3 agent cap). A call that hits it (`error_max_budget_usd`) brings no answer, like any infrastructure error. The cap is not recorded in designs or locks, so older experiments resume under the new cap.
- Step 2's limitations still hold: `--wait` ignores judge pauses, and the usage gate leaves out the judge's subscription use.
- The judge's accuracy is still unmeasured; the judge gate measures it before pairs and ticket grading.
