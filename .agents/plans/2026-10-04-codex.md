## Outcome
- `run once --agent codex` and `run calibrate --agent codex` run Codex headless in an isolated checkout. Its runs are graded, recorded, priced and reported the way Claude Code's are.
- Experiments with Codex as the agent:
  - A/A;
  - context A/B ("does my AGENTS.md change help Codex?");
  - model A/B within Codex.
- Then mixed experiments: `experiment new --a claude:MODEL[:EFFORT] --b codex:MODEL[:EFFORT]`.
- The ChatGPT subscription is first-class, with its usage windows. An API key is the alternative.
- Claude Code's runs, records and reports do not change.

## What Codex does (findings, 2026-10-04)
**How this was checked:**
- **[local]:** Codex CLI 0.160.0 (Homebrew cask, installed 2026-10-04), probed with an empty, throwaway `CODEX_HOME` and no credentials. There was no model call and no sign-in.
- **[docs]:** OpenAI's [docs](https://learn.chatgpt.com/docs/non-interactive-mode) or the [openai/codex](https://github.com/openai/codex) repository (main branch), which may differ from 0.160.0.

**Running headless:**
- `codex exec --json` prints JSON lines:
  - `thread.started` (with `thread_id`), `turn.started`, `turn.completed` (with `usage`), `turn.failed` and `error`;
  - `item.started`, `item.updated` and `item.completed`, for these item types: `agent_message`, `reasoning`, `command_execution` (command, output, exit code, status), `file_change`, `mcp_tool_call`, `collab_tool_call`, `web_search`, `todo_list` and `error`.

  Sources: [exec_events.rs](https://github.com/openai/codex/blob/main/codex-rs/exec/src/exec_events.rs) [docs]; the flags [local].
- It takes the prompt as an argument or on stdin, and reads stdin whenever stdin is piped [local].
- **Exit codes:** 0, or 1 for any turn error, git-check failure or config failure [docs: `exec/src/lib.rs`].

**Tokens, cost and usage windows:**
- `usage` has `input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens` and `reasoning_output_tokens`, counted per turn. One `exec` is one turn, so the stream's counts arrive only at the end. No event has a cost, and the model catalog has no prices [docs; local catalog].
- [spike] The rollout is written live: a `token_usage_record` per model response, as it ends, and a `token_count` that can lag by a whole tool call. Cached input is part of `input_tokens`, and reasoning is part of `output_tokens`.
- Counts per request, and the ChatGPT plan's limit windows (primary and secondary: `used_percent`, `window_minutes`, `resets_at`), come in `token_count` events. The session rollout keeps those events in every mode ([protocol.rs](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs), rollout `policy.rs`) [docs].
- The app server reports the same through `thread/tokenUsage/updated` and `account/rateLimits/updated` [local: generated schema].

**Stopping and network failures** [local]:
- On SIGINT, exec exits 1 and prints no final event, so the stream holds no usage. [spike] Mid-turn too: it exits 1.2–1.3 s after the signal, and the rollout keeps every request's usage and a `turn_aborted` event.
- Without network it never fails. It prints `error` events ("Reconnecting... waiting for network") without end, so only a timeout stops it. [spike] With `--disable unbounded_connection_retries` it ends in `turn.failed` and exit 1 after about 32 s.

**Models and effort** [local catalog]:
- Set with `-m MODEL` and `-c model_reasoning_effort=…`.
- The catalog lists `gpt-6.1-sol`, `gpt-6-sol`, `gpt-6-astra`, `gpt-6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` and `gpt-5.5`.
- Efforts run from `low` to `ultra`, depending on the model.
- The "fast" tier costs twice the usage.
- A thread's model can be rerouted mid-thread (`model/rerouted`, for "highRiskCyberActivity") [local schema].

**Sandbox, which on macOS is Seatbelt:**
- `--sandbox read-only|workspace-write|danger-full-access`. exec never asks for approval [docs].
- In workspace-write, `.git`, `.agents` and `.codex` stay read-only inside writable folders ([security docs](https://learn.chatgpt.com/docs/agent-approvals-security)).
- Permission profiles (`[permissions.NAME.filesystem]` with `read`, `write` or `none` per path; `[permissions.NAME.network] enabled = false`) checked with `codex sandbox -P` [local]:
  - a path set to `none` cannot be read, in both of its `/tmp` forms;
  - writes work only in the listed folders: not `/tmp`, not `$TMPDIR`;
  - `.git` is read-only;
  - there is no DNS and no loopback bind.
- **Nesting fails:** inside an outer `sandbox-exec`, Codex's own sandbox helper stops with `sandbox_apply: Operation not permitted` [local].

**Environment:**
- `codex sandbox` hands the whole parent environment to its command [local].
- exec filters what commands get through `shell_environment_policy` (`inherit`, `filters`, `set`) [docs].

**Sign-in** ([auth docs](https://learn.chatgpt.com/docs/auth)):
- Methods: a ChatGPT login (browser or device code); an API key (`CODEX_API_KEY` for exec, `OPENAI_API_KEY`); an enterprise access token.
- Credentials sit in `$CODEX_HOME/auth.json` (plain text) or in the keyring (`cli_auth_credentials_store`).
- ChatGPT tokens refresh during use, and the new ones are written back to `auth.json`.
- OpenAI recommends API keys for programmatic and CI use.
- `--ignore-user-config` skips `config.toml`, but sign-in still uses `CODEX_HOME` [local help].
- Here, the user's `~/.codex/auth.json` exists. Only its presence was checked; it was not read.

**State in `CODEX_HOME`:**
- One throwaway exec wrote these there: state, logs, memories, goals and queue SQLite files; shell snapshots; an installation ID; bundled skills [local].
- Without `--ephemeral`, sessions go to `sessions/`; `sqlite_home` and `log_dir` move part of the rest [docs].
- Codex refuses to create its helper aliases (`apply_patch`) when `CODEX_HOME` lies under the temp folder [local].
- A managed Codex app-server daemon runs from `~/.codex` on this Mac, seen in the process list [local].

**Context** (checked with `codex debug prompt-input`, which is free and works offline) [local]:
- **AGENTS.md:** the files from the git root down to the starting folder, where a folder's `AGENTS.override.md` replaces its `AGENTS.md`.
- **Size cap:** 32 KiB for all of them together. A 40 KB root file was cut, and the nested file dropped.
- **Not followed:** `@imports` stay plain text.
- **Never loaded:** `CLAUDE.md` and `.claude/skills`.
- **Skill descriptions from four places:**
  - `<repo>/.agents/skills` and `<repo>/.codex/skills`;
  - `$HOME/.agents/skills`, the user's own (a throwaway run listed one);
  - the bundled `$CODEX_HOME/skills/.system`.

  A run-local `HOME` drops the user's own.
- **[docs]:**
  - also `$CODEX_HOME/AGENTS.md` and `project_doc_fallback_filenames`;
  - only for trusted projects: `.codex/config.toml`, hooks and rules.
- **On by default** [local `features list`]: multi-agent tools, the code-mode host, apps, plugins, browser and computer use, image generation, and hooks. The catalog sets `gpt-6.1-sol` to `tool_mode: code_mode_only`.

## Design
### The agent seam (`internal/agent`)
- An agent-neutral `Invocation`, which today's `claude.Invocation` fields split into:
  - shared: start folder, checkout, prompt, model, effort, cap, sign-in, denied paths, build cache, temp root, tools, deps, local binding;
  - agent-specific options.
- `Metrics`, the fields both agents fill:
  - version, model, cost and its source, tokens, duration;
  - commands, file paths, tool uses, denials;
  - result, usage readings, first-request tokens.

  The Claude-only fields stay in the JSON as they are today.
- An `Adapter` with `Command`, `DeniedPaths`, `Parse`, `Classify`, `Check` and `Version`.
- `internal/claude` is the Claude Code adapter, unchanged. A golden test of its arguments, environment, settings and denied paths is written first.
- The shared parts move to `internal/sandbox`:
  - the deny list (Agentium's data, the user's repository, other runs, credential stores, the user's build caches, shared temp and log folders);
  - the environment allowlist (`EnvironFor`).

### The Codex adapter (`internal/codex`)
- **Command:**

  ```
  codex exec --json -m MODEL -c model_reasoning_effort=E --ignore-user-config -c ... -C DIR [--add-dir REPO] -o <records>/last-message.txt
  ```

  The prompt goes on stdin; never `--dangerously-*`. The effort is always passed (the catalog default when none is given), because the rollout records it only then [spike].
- **Environment:**
  - the allowlist;
  - `CODEX_HOME`: in login mode, the shared login home `~/.agentium/codex`, since the sign-in and the `sessions/` folder both live there and no setting moves sessions [spike]; in API-key mode, the run's own, in its workspace, not under the temp folder;
  - `HOME`: the run's own, so the user's skills do not load;
  - in API-key mode, `CODEX_API_KEY`.

  The agent's shells get the user's `HOME` back and never the key. `shell_environment_policy` needs `ignore_default_excludes=false` (it defaults to true from TOML in 0.160.0, which turns the `*KEY*` filter off) and `exclude=["CODEX_*","OPENAI_*"]`; `set` gives the run's `TMPDIR` and `TMPPREFIX` (zsh writes heredocs under `TMPPREFIX`, `/tmp/zsh` by default) [spike].
- **Run-local settings that Agentium passes** as `-c` overrides with `--ignore-user-config`; exec has no config-file flag, and `-p` profiles live in `CODEX_HOME` [spike]:
  - **Approvals:** `approval_policy = "never"`.
  - **The `agentium` permission profile:**
    - the disk is readable;
    - the checkout, the build cache and the run's temp root are writable;
    - deps are read-only;
    - every denied path Claude's runs get is `deny` (`none` is a legacy alias), and so are `~/.codex` and `~/.agents`; `~/.agentium` covers the shared login home;
    - network off.
  - **Project trust pinned:** `-c 'projects={"<checkout>"={trust_level="untrusted"}}'`. Otherwise exec trusts the checkout and saves that in `CODEX_HOME/config.toml`; the dotted-key form is ignored [spike].
  - **State in the run:** `sqlite_home` and `log_dir` in the run's folder, `history.persistence="none"`.
  - **Off:**
    - web search, apps, plugins, browser and computer use, image generation and memories;
    - hooks and tool suggestions;
    - daemon auto-start, the update check and the fast tier;
    - unbounded connection retries (`unbounded_connection_retries`).

    `view_image` stays on: the sandbox denies it the deny list [spike].
  - **Sign-in:** `forced_login_method` fixed to the sign-in mode.
- **Parsing:** the JSONL stream and the run's own rollout file go into `Metrics`:
  - requests and tokens from `token_usage_record`, priced per request;
  - rate-limit windows from `token_count` (`primary` and `secondary` only; never `plan_type` or `credits`);
  - the session's model, effort, sandbox and approval (`session_meta`, `turn_context`); never `creator_user_id` or `creator_account_id`;
  - commands and changed files;
  - denials, from the rollout's `custom_tool_call_output`: sandbox-denied commands and failed `apply_patch` or `view_image` calls leave no item in the stream [spike];
  - reroutes, from the stream (`item.completed` with an `error` item, `model rerouted: ...`): the rollout does not keep them [spike];
  - the final message.
- **Outcomes:**
  - `ok`;
  - `capped`, at Agentium's cap;
  - `timeout`;
  - `infra`: no `turn.completed`; "Reconnecting" or "waiting for network"; a usage limit; a sign-in failure;
  - `unfair`: drift in version, model, effort, sandbox or skill set, or a reroute;
  - `cancelled`.
- **The cost cap is Agentium's**, because Codex has none:
  - Agentium watches the rollout's `token_usage_record` lines and prices them; `token_count` can trail by a whole tool call [spike].
  - Past the cap, it stops the run (SIGINT, then SIGKILL). Exit took 1.2–1.3 s in the spike.
  - The overshoot allowance is one whole request, since a request in flight at SIGINT is never recorded: at most the effective context (258,400 input tokens for `gpt-6.1-sol`) plus its output [spike].
  - An interrupted run's spend is read from the rollout.
- **Leftovers:** unified exec gives each command its own PTY session, outside the process group. After every run, Agentium sweeps the processes still using the workspace (the existing sweep). In the spike none were left, even after SIGINT with a `sleep 900` session and a `nohup` child running; `setsid` was not tried.
- **After each run (login mode):** Agentium moves the run's rollout (found by `thread_id`) from the shared `sessions/` to the run's records, and deletes a leftover `shell_snapshots/<thread>.*.sh`, which SIGINT leaves behind [spike].
- **Discovery:**
  - `AGENTIUM_CODEX`, else `PATH`;
  - the version;
  - the sign-in mode, by presence only.

### Pricing
- `internal/pricing` gets OpenAI's dated table: input, cached input, cache writes and output, with reasoning counted as output.
- The long-context rate applies above 272K input tokens per request. Only the standard tier is used.
- A lock records each table's date.

### Context per agent
- `claudectx` gains a Codex view, built on the findings above.
- **Loaded:**
  - the AGENTS.md chain;
  - skill descriptions from `.agents/skills` and `.codex/skills`.
- **Classed as harness, not loaded** (the checkout is untrusted; decision 7): `.codex/config.toml`, rules and hooks.
- **Snapshots** take Codex-only files (`AGENTS.override.md`, `.codex/skills`).
- **Commands:** `context show --agent codex`.
- **Lint:** its "@imports unverified" note becomes verified.
- **Calibration** works as for Claude: a short paid run repeats a probe that is appended to the AGENTS.md Codex loads.

### Experiments
- **Agent per design:** `--agent` on `experiment new`, `start` and `run`, defaulting to Claude Code.
- **Agent per arm:** `agent-ab` arms write `AGENT:MODEL[:EFFORT]`. The efforts are each agent's own.
- **A new design version:** an older Agentium refuses such designs, since it would run Claude Code.
- **The lock records:**
  - each agent's version, path and sign-in mode;
  - each price table's date.

  A resume refuses version drift, as it does today.
- **Calibrations are per agent:** a migration adds an `agent` column, defaulting to `claude-code`.
- **Usage pauses per vendor:** Claude's five-hour window, and the ChatGPT plan's primary and secondary windows.
- **Preview:** priced from the agent's past runs, else a default per model.

### Records and reports
- Records add `"agent"`; an absent key means Claude Code.
- **Reports show:**
  - the agent and version per arm;
  - each agent's effective context, side by side;
  - the cost source per arm;
  - in a mixed experiment, the differences listed under [fairness](#fairness-claude-code-against-codex).
- A report without Codex runs does not change.

### The judge stays Claude Code
- It reads only the instruction and the diffs, so it is agent-neutral.
- Without a Claude sign-in, judge options are refused.
- In a mixed experiment, the report says that Claude judges Claude's work too. Its results stay exploratory.

### Containers (after the container track's executor)
- **Image:** a Codex layer with a pinned binary.
- **Network:** egress only to OpenAI's API hosts.
- **Sign-in:** `CODEX_API_KEY` passed by name.
- **Sandbox:** Codex's own sandbox off inside the container, since the container is the boundary; or Linux `bwrap` where it works.
- The executor is recorded, and an experiment never mixes executors (the [decision](../decisions/2026-10-02-containers-direct-docker.md)).
- A ChatGPT login inside a container waits: its token refresh writes `auth.json` back.

## Fairness: Claude Code against Codex
- **The same task:** both agents get the same:
  - base commit, instruction and Agentium suffix, and start folder;
  - hidden tests and verification;
  - timeout and cap;
  - environment allowlist, denied paths, writable folders and no network;
  - machine and grader.

  Only the agent, its model, its tools and how it loads context differ.
- **Context:** each agent loads what it would in the user's own sessions:
  - Claude Code: `CLAUDE.md` (else `AGENTS.md`), imports, rules and skills;
  - Codex: the AGENTS.md chain, up to 32 KiB, and its skill folders.

  The verdict answers: which agent does better on this repository as it is set up. Reports warn when one side loads little, such as a repository with only `CLAUDE.md`. There is no silent fallback (`project_doc_fallback_filenames`) in v1.
- **Tools:**
  - Both lose outward-facing tools.
  - Both keep sub-agents: Claude's Task, Codex's multi-agent tools.
  - The tool sets differ by design; reports list them and never compare them.
- **Cost units:**
  - Dollars at list prices on both sides: Claude Code's own figure, and Codex's tokens priced by Agentium.
  - Tokens and turns are never compared across agents: the tokenizers differ, and a "turn" means different things.
  - Subscription window shares are per vendor: shown per arm, never a verdict.
- **Sandbox parity:** each agent runs in its vendor's own Seatbelt sandbox, with Agentium's deny list, writable folders and no network. Known gaps:
  - Codex keeps `.git`, `.agents` and `.codex` read-only, so a task whose reference changes them is refused for Codex arms.
  - Claude's file tools are checked by permission rules; Codex works only through its sandboxed shell, code mode and `apply_patch`.
  - Gradle's local binding stays Claude-only. Codex's only equivalent, the experimental `network_proxy` mode with `allow_local_binding`, also lets DNS out to any resolver [spike].
- **Noise:** an A/A per agent. Codex verdicts count only after its own A/A passes.

## Boundaries
- **No new modules or SDKs:** no new Go modules and no Codex SDK. Codex runs as a CLI in its own process.
- **Never on the host:** `--dangerously-bypass-approvals-and-sandbox`, `danger-full-access` or `--dangerously-bypass-hook-trust`.
- **Credentials:** Agentium never reads, copies or writes a Codex credential, and never runs `codex login` or `logout`. It never uses, reads or writes `~/.codex`. The user signs in.
- **No background processes:** Agentium starts none, and Codex's daemon stays off.
- **Paid runs** need the user's approval and an estimate (steps 1 and 7).
- **Unchanged:** Claude Code's behavior and records; the judge stays Claude Code.
- **Reviews:** security steps (2, 3, 5, 6, 8) get the reviewer's threat checklist.
